# Public Telemetry Dataset Survey

Status: **Reviewed research**

Verified: **2026-09-22**

## Purpose

Identify public telemetry data that can challenge OME's domain and architecture assumptions before feature implementation.

This document separates:

- **vendored fixture** — copied into OME with a clear redistribution basis;
- **external validation source** — publicly accessible and useful, but not copied into OME;
- **reference only** — useful context but not appropriate as a first fixture.

Public accessibility is not treated as automatic redistribution permission.

## 1. exit_speed — real telemetry project

Repository:

https://github.com/djhedges/exit_speed

The project documents race-car telemetry work and includes public test data.

### Small fixture reviewed

Upstream path:

`exit_speed/testdata/test_parking_lot_20hz_2020-06-11T22_1.csv`

Observed structure:

- metadata preamble:
  - format;
  - track;
  - vehicle;
  - driver;
  - date/time;
  - sample rate;
  - duration;
- sample columns:
  - elapsed time;
  - latitude;
  - longitude;
  - altitude;
  - velocity;
  - lap.

Direct inspection:

- 1,962 sample rows;
- approximately 196.1 seconds;
- regular 10 Hz cadence;
- three lap identifiers;
- varying GPS and velocity.

OME decision:

A copy is included under `fixtures/public/exit-speed/` with the upstream Apache-2.0 license.

### Larger real-track data

The same upstream project includes substantially larger telemetry from Portland International Raceway.

OME decision:

Keep those files external for now to avoid unnecessary repository growth. They are strong candidates for performance/integration benchmarks later.

## 2. teamjorge/ibt — public iRacing binary fixture

Repository:

https://github.com/teamjorge/ibt

Public test file inspected:

`.testing/valid_test_file.ibt`

Upstream Git blob SHA:

`bd1b0123067fec0fe6bdf68a95b562394d944874`

Direct binary inspection found:

- file size: 471,844 bytes;
- iRacing telemetry version: 2;
- tick rate: 60 Hz;
- 276 telemetry variables;
- 390 records;
- one recorded lap in the file header;
- embedded session information;
- track metadata for Red Bull Ring / Spielberg GP;
- source channel names, descriptions and units.

Relevant source channels include:

- SessionTime;
- SteeringWheelAngle;
- Throttle;
- Brake;
- Gear;
- RPM;
- Lap;
- LapDist;
- LapDistPct;
- Speed;
- YawRate;
- LatAccel;
- LongAccel.

The source describes `Speed` specifically as GPS vehicle speed, which is useful evidence for OME's rule that source semantics must remain preserved.

OME decision:

Use as an external validation source.

Do not vendor the binary into OME yet. Although the parser repository is Apache-2.0, the binary is generated by a proprietary simulator and redistribution rights were not independently cleared during this review.

## 3. CR Formula — real Formula SAE data

Repository:

https://github.com/CR-Formula/FSAEElectrical

The repository publishes CSV logs from testing and competition, including:

- Autocross;
- Skidpad;
- Practice;
- Endurance.

### Casey Autocross file reviewed

Upstream path:

`Logs/CR-27 Michigan/Autocross/Casey Autocross.csv`

Upstream Git blob SHA:

`86460bfccde68344f61b7dba7ca883cfcb0c591f`

Channels include:

- sample number;
- UNIX timestamp;
- RPM;
- TPS;
- fuel open time;
- ignition angle;
- lambda;
- air temperature;
- coolant temperature;
- latitude;
- longitude;
- speed;
- oil pressure.

Direct inspection found:

- 7,179 rows;
- approximately 211 seconds;
- median timestamp interval around 31 ms;
- apparent average cadence around 34 Hz;
- a maximum observed timestamp gap above 5 seconds;
- RPM/TPS/oil-pressure channels substantially populated;
- latitude, longitude and speed columns present but all-zero in the inspected file.

A particularly useful inconsistency is that the sample-number column label claims "10000 samples per second" while recorded UNIX timestamp cadence is nowhere near 10 kHz.

OME decision:

External validation source only.

No explicit repository-level redistribution license was found during this review, so OME should not copy these logs into its public repository without permission.

## 4. TRACE — MoTeC-style fixtures

Repository:

https://github.com/keystroke-tools/TRACE

License:

MIT.

Vendored examples:

- `motec-canonical.csv`
- `motec-decreasing-time.csv`

These are synthetic rather than real race telemetry.

They are valuable because they exercise:

- MoTeC metadata preamble;
- channel-name row;
- unit row;
- numeric and discrete values;
- missing-like text;
- decreasing time.

## 5. MoTeC official/public samples

MoTeC i2 supports exporting channel data to CSV and the vendor ecosystem exposes public sample/forum data.

OME decision:

Treat public MoTeC `.ld` downloads as external validation material unless a specific file has redistribution permission appropriate for OME.

The first OME professional workflow remains MoTeC CSV export.

## 6. Brazilian public-data gap

The review found public Brazilian Formula SAE telemetry tooling/projects, including B'Energy Racing and Icarus/UFRJ-related telemetry work.

However, this pass did **not** identify a full, representative Brazilian vehicle-session dataset with a sufficiently clear redistribution license to vendor into OME.

This is now a concrete research/outreach gap rather than something OME should pretend is solved.

Recommended future action:

Request permission from Brazilian Formula SAE teams to publish one sanitized OME validation session.

## Recommended fixture roles

### Committed public fixtures

Use for fast deterministic tests:

- small Traqmate CSV from exit_speed;
- TRACE MoTeC canonical CSV;
- TRACE decreasing-time negative fixture;
- future project-owned OME CSV fixtures.

### External integration fixtures

Use for richer/manual or optional validation:

- teamjorge iRacing `.ibt`;
- CR Formula competition/test CSVs;
- large exit_speed Portland race-track logs;
- explicitly permitted MoTeC sample logs.

### Private validation fixtures

Later, teams may provide telemetry that cannot be committed publicly.

The harness must support testing against those datasets locally without requiring them in the open-source repository.
